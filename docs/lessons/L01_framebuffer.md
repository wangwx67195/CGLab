## 1. 这节课为什么值得做？

后面所有算法——画三角形、填 Z-buffer、贴纹理、光线追踪、路径追踪——最终都要回答同一个问题：**哪个像素应该是什么颜色？**

在使用 OpenGL 之前，先用 CPU 管理一块连续 RGB 内存，并输出一张浏览器/图像查看器能识别的图像。只要真正理解了图片如何从“二维坐标”映射到“一维字节”，就已经迈过构建软件渲染器的第一道门槛。^_^

## 3. 自己动手实现的目标（不提供答案代码）

**输入**：固定 `width = height = 256`，RGB 各通道为 `[0,255]` 整数。

**输出**：`outputs/L01_gradient.ppm`，P6（二进制 RGB）PPM 格式，内容包含：

- 背景渐变：红通道仅随 `x` 从左向右 0→255；绿通道仅随 `y` 从上到下 0→255；蓝通道固定为 128。
- 图片中心叠加白色实心矩形，范围是 `96 <= x < 160` 且 `96 <= y < 160`（**半开区间**）。
- 画布外不写入；索引越界时**显式拒绝/报告**，不得悄悄破坏内存。
- 最终文件要能被图片查看器打开。可先导出只包含渐变的图，确认正确后再叠加矩形。

### 理论提示（公式可以给，循环自己写）

对于整数像素坐标：`0 <= x < width`、`0 <= y < height`，RGB 首字节的零基偏移为：

\[
\text{offset}(x,y) = 3(y\cdot width + x)
\]

渐变（整数计算时注意四舍五入或截断策略）：

\[
R(x,y) = 255\frac{x}{width-1},\qquad
G(x,y) = 255\frac{y}{height-1},\qquad
B(x,y) = 128.
\]

**本课约定**：`width,height >= 2`，因此 `width - 1` 不为 0。通道由浮点值转换为 `uint8_t` 前先确定取整及截断规则，确保不会超出 `[0,255]`。

### 建议的函数职责（签名与实现由你拟定）

1. 初始化一个 `width * height * 3` 大小的缓冲区；
2. `set_pixel`：给指定 `(x,y)` 写三个 RGB 字节，并进行边界检查；
3. `draw_gradient`：把整张画布变成背景渐变；
4. `draw_filled_rectangle`：覆盖中心区域；
5. `save_ppm`：把图像按 P6 格式输出为文件；
6. `main`：连接这些步骤，并检查错误返回值。

**请你先自行选定参数类型**：例如宽/高用 `int` 还是 `std::size_t`？颜色用 3 个 `uint8_t`、`std::array` 还是结构体？为什么？这里没有唯一“最佳”答案，重点是约定一致。

## 4. 你会用到的 API（仅说明用途，不拼成解答）

| API / 关键词 | 主要用途 | 关注细节 |
|---|---|---|
| `std::vector<std::uint8_t>` | 保存连续像素字节 | `size()` 是字节个数；`operator[]` 默认不做边界检查，调试可考虑 `.at()` |
| `std::size_t` | 容量和数组索引 | 与有符号 `int` 混合时警惕隐式转换 |
| `std::ofstream` | 写出图片文件 | 检查是否成功打开；二进制输出要用 `std::ios::binary` |
| `operator<<` | 写 PPM ASCII 文件头 | 文件头与 RGB payload 是两种不同的写入形式 |
| `std::ostream::write` | 写原始 RGB 字节 | 参数需要指向连续内存及实际字节数；不是输出十进制文本 |
| `std::clamp`（C++17，可选） | 限定颜色范围 | 范围和类型要一致；注意转换到整数之前/之后的行为 |
| `std::filesystem`（C++17，可选） | 输出前创建目录 | 无法创建路径时应报告错误 |
| `add_executable` / `CMAKE_CXX_STANDARD` | 告诉 CMake 构建本课程序 | 它们只处理构建，不帮你实现像素算法 |

> 需要学习某个 API 时，向 Agent 索取**孤立的 1–6 行示例**与参数说明即可；不要让 Agent 替你完成 `main.cpp`。

## 5. 输出文件格式：PPM P6

P6 文件结构：先写 ASCII 文件头 `P6`、宽高、最大颜色值 `255`，再写严格按行排列的 RGB 原始字节。推荐的头部文字为（每行末尾是换行）：

```text
P6
256 256
255
```

**警告**：PPM 头部是文本，后面的二进制数据不是 `0`、`255` 等数字字符串，而是每像素连续的 3 个原始字节。按此确切文件头布局，头部占 15 字节，像素数据应占 `256*256*3 = 196608` 字节，总长度应为 **196623 字节**。

- [ ] 对超出边界的坐标调用 `set_pixel` 时不发生未定义写入。
- [ ] 学生能解释像素寻址、通道排列、文件头与坐标原点约定。

### 可选挑战（二选一）

- 以 `16×16` 分辨率绘制黑白棋盘格，验证离散坐标和小图像效果。
- 支持命令行输入尺寸（要求 `width,height >= 2`），并处理非法尺寸与文件路径。

### 典型错误与排查方向（非答案）

- 图像上下颠倒：检查 `y` 增大方向与写文件行顺序。
- 红绿颜色位置混乱：检查通道排列和 `(x,y)` 的参数顺序。
- 文件打不开：先检查 ASCII header、空格/换行、二进制模式和总字节数。
- 编译成功却一片黑：先在一个固定像素上写入明确颜色，再逐步检查渐变公式。
- 越界/崩溃：检查 `0 <= x < width` 与 `0 <= y < height` 的半开区间。
